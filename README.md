# Chika · Shift Control

Приложение для управления сменой одной кофейни: обзор смены, задачи и чек-листы, регистрация инцидентов. Мягкий серый интерфейс адаптирован для компьютера и телефона. Языки — русский и английский, переключатель RU / EN находится сверху.

## Текущая версия

- Обзор смены: открытие/закрытие, показатели, команда, заметка.
- Задачи: чек-листы, добавление, выполнение и фильтры.
- Инциденты: создание, приоритеты, статусы и фильтры.
- Выбор языка и изменения сохраняются в браузере.
- Исходные задачи — демонстрационные примеры. Настоящих аккаунтов, API и общей базы данных пока нет.

У каждого браузера отдельные данные. Изменения не передаются другим сотрудникам. Переход с localhost на опубликованный сайт не переносит сохранения автоматически. Не вводите в демонстрацию персональные и рабочие данные.

## Технологии

Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4 и Lucide. Команды разработки и сборки используют Webpack. Изображения находятся в public/; внешних шрифтов и аналитики нет.

## Запуск на macOS

Установите Node.js 24 LTS с https://nodejs.org — npm входит в комплект. Глобальные инструменты не нужны.

Скачайте или клонируйте этот репозиторий. В Терминале перейдите в его папку (замените путь на свой):

```bash
cd ~/Projects/chika-shift-control
npm ci
npm run dev
```

После Ready откройте http://localhost:3000. Оставьте терминал открытым. Остановка: Control+C.

## Запуск на Windows

Установите Node.js 24 LTS. В PowerShell или Командной строке перейдите в папку проекта (замените путь на свой):

```powershell
cd C:\Projects\chika-shift-control
npm ci
npm run dev
```

После Ready откройте http://localhost:3000. Если PowerShell блокирует npm.ps1, используйте npm.cmd вместо npm или откройте Командную строку. Менять политику безопасности не требуется.

## Проверка и готовая сборка

Выполняйте команды по очереди:

```bash
npm run typecheck
npm run build
npm start
```

Для проверки на iPhone используйте готовую сборку: iPhone и компьютер должны находиться в одной сети Wi-Fi. В Safari откройте http://IP-КОМПЬЮТЕРА:3000. Компьютер и терминал должны оставаться включёнными. localhost на телефоне обозначает сам телефон.

## Публикация

GitHub хранит исходники и историю изменений. Доступ к опубликованному сайту управляется отдельно на хостинге. Приватный репозиторий может быть источником публичного сайта.

Текущая сборка — Next.js-приложение. Для автоматической публикации подключите репозиторий к хостингу с поддержкой Next.js, например Netlify или Vercel, и следуйте его настройкам. Сам перенос на GitHub не подключает автоматическую публикацию и не меняет существующий сайт. Для ручного статического экспорта нужен отдельный next.config.mjs с output: 'export' и trailingSlash: true; после npm run build на статический хостинг загружается папка out/.

## Структура

- app/page.tsx — обзор смены.
- app/tasks/page.tsx — задачи.
- app/incidents/page.tsx — инциденты.
- app/globals.css — оформление.
- components/store.tsx — состояние и localStorage.
- components/language.tsx и lib/translations.ts — языки интерфейса.
- lib/data.ts — типы, смены, обязанности и перенос старых сохранений.
- public/ — логотип и иллюстрация кофейни.

Задачи, инциденты, заметка и состояние смены: shift-control:v1. Язык: shift-control:language. Ранее выбранный логотип: shift-control:logo:v1. Очистка данных сайта удаляет эти сохранения.

## Обновление: смены, роли и срочные проблемы

- Имена сотрудников удалены из интерфейса и назначений. Назначения — «Бариста» и «Хэд-бариста», это пока обязанности, а не настоящие разрешения доступа.
- Утро 07:30–14:30, мидл 09:00–16:00, вечер 14:30–21:00. Выбор смены доступен на каждой странице, сохраняется в браузере. У каждой смены отдельные задачи, статус и заметка для передачи.
- На главной раскрывается полный список 12 обязанностей хэд-бариста, предоставленный владельцем. Задачи бариста — редактируемые примеры; окончательный список ещё не согласован.
- В задачах есть фильтр по роли, создание и редактирование. Время новых/редактируемых задач ограничено интервалом смены.
- Сообщить о проблеме можно в разделе «Инциденты», кнопка «Сообщить о проблеме». Для срочной ситуации выберите высокий приоритет. Отдельная кнопка «Срочная проблема» убрана.
- Нерешённые проблемы с высоким приоритетом отображаются сверху главной, даже если относятся к другой смене. В инцидентах есть фильтр всех смен.
- Данные остаются локальными. Нет оповещений команды, аккаунтов, гарантированных прав администратора, календаря или истории по дням. Постоянные наборы задач автоматически не сбрасываются.

Сохранения читаются под прежним ключом shift-control:v1, структура обновлена до version:2. При переносе сохраняются задачи, выполнение, заметка и инциденты. Старые назначения заменяются ролями. Старые задачи закрытия переносятся в вечер, остальные — в утро; их исходное время сохраняется. Для смен без старых задач добавляются примеры. Записи старого списка инцидентов и общая заметка относятся к утру. Перед реальной эксплуатацией распределение старых данных следует проверить.

Проверки модели и переноса:

```bash
npm test
```

Для проверок нужен Node.js 24 LTS. Продуктовая цель, ограничения прототипа и план «админ только владелец» описаны в [docs/IOS-AND-ACCESS.md](docs/IOS-AND-ACCESS.md).

## Завершённые записи

Отметка выполнения задачи и перевод инцидента в статус «Решён» требуют подтверждения. После подтверждения выполненную задачу нельзя снять с выполнения, редактировать или переназначить. У решённого инцидента нельзя изменить статус и приоритет. Записи доступны для просмотра. Действие действует и для ранее завершённых записей, загруженных из localStorage.

Блокировка реализована в интерфейсе и в общей функции обновления локального состояния. Она сохраняет исходные поля завершённых записей и восстанавливает их, если обновление пытается удалить запись. Для настоящей защиты от чужих изменений нужны backend, аккаунты и серверная проверка прав. Роль администратора пока не реализована, исключения для него в этой версии нет. Переключатели «админ» в браузере не добавлены. Владелец должен получить право редактирования завершённых записей через подтверждённый серверный user ID после подключения аккаунтов.
